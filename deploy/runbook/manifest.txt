# The checks every run must produce a verdict for, per topology — issue #111, ADR-034.
#
# ⚠️ THIS FILE IS WHY SILENCE CANNOT PASS. run.sh sums verdicts, and a family that dies before it
# speaks, or is never wired in, emits none: without a promise to compare against, "no FAIL" reads as
# success. Every line here is a promise that a verdict will arrive; an id with no verdict is VOID,
# and a VOID exits non-zero exactly as a FAIL does.
#
# It is committed, and it is an INPUT to run.sh — never generated from a run's own output, which
# would make the promise whatever happened to be kept. It is held to the families twice. On every run,
# run.sh refuses a check promised to two families, and voids a family whose own stream reports a check
# this file does not promise it. And RunbookManifestTest reads this file: every family the runbook ships is
# listed and every family listed ships, no check belongs to two families, and each family's declared
# checks — a host script's `family` line, an outside script's `const CHECKS`, each refused by that
# family's own verdict() when anything else is printed — are exactly the rows here, under exactly the
# topologies the family declares — a host script's `topologies` line, an outside script's `const
# TOPOLOGIES`, each refused by the family itself when it is sent to any other host. Every host script but
# common.sh and probe-log.sh, and every outside script, must declare exactly one family, its checks and its
# topologies in a form the test can read, so a family cannot ship without the test seeing it, and a whole
# block of its rows cannot go missing without the test saying so.
#
# Format: <topology> <family> <check-id>, where topology is `tunnel` (stage: cloudflared in front of
# nginx) or `dns-only` (alpha: Forge, no tunnel). Blank lines and # comments are ignored. run.sh refuses a
# row with any other topology, which no run would select, and a family name that is not one plain path
# segment, since it names the family's script and its output file.
#
# ⚠️ FAMILIES APPEAR HERE ONLY WHEN THEY LAND. The runbook is being written family by family, each
# proven on stage before the next (deploy/runbook/README.md). A family listed before its script
# exists would make every run VOID, which is correct but useless; a family that lands without being
# listed here would make every run vacuously green, which is the failure this file exists to stop.
# The test enforces the second direction, so the only way to land a family is to list it.

# --- plumbing (common.sh, run.sh): no checks of its own; proven by RunbookManifestTest ---

# --- relays (host/relays.sh) ---
# ADR-034's central condition. The same ids on both topologies, and the expectation differs: on a
# tunnel host exactly one process may dial the web server over loopback, and on a DNS-only host none
# may. RLY-1 drives its own traffic, because an idle connector holds no connection to find.
tunnel   relays RLY-1
tunnel   relays RLY-2
tunnel   relays RLY-3
tunnel   relays RLY-4
tunnel   relays RLY-5
dns-only relays RLY-1

# --- the tunnel hostnames (outside/tunnel-log.php, driving host/probe-log.sh) ---
# ⚠️ TWO IDS, NOT ONE PER HOSTNAME. This file is static and committed, and a server's hostnames are a
# property of that server, so a per-hostname id could never be promised in advance. TUN-1 covers the
# requests across every hostname the server serves — one failing hostname fails it, and each one's
# detail is recorded — and TUN-2 covers the probe log being removed afterwards.
#
# There are no dns-only rows because the family declares `tunnel` alone: alpha has no tunnel, and its own
# family judges what a request without one must look like. Run on any other topology, this family says so as
# a VOID rather than skipping, so the gate cannot read it as a family that died.
tunnel   tunnel-log TUN-1
tunnel   tunnel-log TUN-2
# --- the throttle at PHP (outside/throttle.php, driving host/probe-log.sh and host/throttle-store.php) ---
# ⚠️ THREE IDS, NOT ONE PER HOSTNAME, for the reason tunnel-log gives above. THR-1 covers the requests
# across every hostname the server serves — the login throttle's key holds no hostname, so all of them
# share one bucket per address, and one failing hostname fails it — THR-2 covers what that bucket is keyed
# on, and THR-3 covers the probe log being removed afterwards.
#
# ⚠️ A RUN LOCKS SIGN-IN OUT, DELIBERATELY. It signs in wrongly
# seven times plus once more for every hostname the server serves — ten against a host serving three —
# from the operator's address, and leaves Filament's login throttle tripped for that address, on every
# hostname at once, for up to 60 seconds. That is the measurement, not a side effect: run it against stage
# or a not-yet-live alpha, in a maintenance window.
#
# There are no dns-only rows yet. The family declares `tunnel` alone, and the dns-only rows land with the
# alpha bring-up, when a real dns-only host has produced them — a family is promised for a topology only
# once some host has exercised it (README.md). Run on any other topology this family says so as a VOID
# rather than skipping, so the gate cannot read it as a family that died.
tunnel   throttle THR-1
tunnel   throttle THR-2
tunnel   throttle THR-3
